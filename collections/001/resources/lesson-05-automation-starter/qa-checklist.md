# B.O.B. Lesson 05 — Acceptance checklist

- [ ] Learner chose an LLM and generated a personalized prompt
- [ ] Learner distinguished queued / attempted / delivered / inbox placement
- [ ] Learner simulated new send cap separate from follow-up volume
- [ ] Suppressed/opted-out fictional records never receive eligible status
- [ ] Learner tested different caps without real email delivery
- [ ] Learner recognizes calendar free/busy as an API check, not guesswork
- [ ] Learner exports a fictional CSV and retains editable source
- [ ] Learner understands persistent backend, provider permissions and consent are needed for real deployment
- [ ] Costs, data ownership, account control, recovery and licensing are documented
- [ ] Before production: opt-out, authentication, audit logs, test inboxes and failures are verified

**Pass criteria:** Another beginner can reproduce the demo without B.O.B.'s accounts or credentials. A demo that does not send email must never be called a functioning email campaign.
