Build and launch a website you own.

Use the LLM of your choice, GitHub, and either GitHub Pages or Cloudflare Pages to publish a simple business website. Start with a working site you can edit and export. No monthly website-builder subscription is required for the core demonstration.

What we're actually demonstrating

AZHomeInstalls uses a public site backed by GitHub and Cloudflare, with additional CRM, scheduling and security components. This lesson reproduces the static public website foundation only. It does not pretend that uploading HTML automatically provides an estimate system, database, booking engine, or payment processing.

Successful learner outcome: a live mobile-friendly site in their own repository, with accurate content, a working email contact link, and control of the source files.

Step 3 — Start from a working website

For beginners, downloading a proven two-file starter is safer than generating an entire application without understanding it. Open the GitHub file pages below and save both files into the same folder, then ask your LLM to customize them. The files remain yours to edit.

Open / save index.html — website structureOpen / save styles.css — design and mobile layoutDownload setup instructions (README.md)
1. Download.

Save index.html and styles.css in the same folder. Don't change extensions. On GitHub, tap the file, then use the download icon or the three-dot menu's download option. Save both files in the same folder in the Files app. If your browser only opens a preview, use GitHub's Raw/Download raw file action, then Share → Save to Files.

2. Customize.

Replace “YOUR BUSINESS,” the services, description and placeholder email. Update colors in styles.css. Your LLM can explain each change, but you should review it before publishing.

3. Preview.

Open index.html locally in a browser or use a code preview environment. Confirm the layout, buttons, and links on phone and desktop.

4. Create your GitHub repository.

Sign in to a GitHub account you own; choose a unique repository name, then upload the two files to its root. If you prefer a private source repository, verify that your chosen publishing approach supports it before deployment.

Step 4 — Publish, using your own accounts

Route A: GitHub Pages

Open the repository’s Settings → Pages. For a basic static site, select deployment from a branch, then your main branch and root folder, where supported. Save and use the URL displayed by GitHub Pages. Publishing settings and permissions can depend on plan and repository visibility.

Official GitHub Pages quickstart ↗

Route B: Cloudflare Pages

In a Cloudflare account you own, create a Pages project and connect your GitHub repository, or use supported direct uploads. For this static starter, no build command or framework is needed. Follow the provider’s current setup prompts and verify the deployment link. A custom domain is optional.

Cloudflare Pages Git integration docs ↗

GitHub Pages and Cloudflare Pages are alternatives for this basic deployment; you do not need both. Free-tier availability, usage limits and custom-domain charges can change, so check the current official pricing before upgrading.

Step 5 — Test and maintain your site

  • Open the deployed HTTPS URL in a private browser window.
  • Inspect it on a phone: no cut-off menus, text, or buttons.
  • Confirm all navigation and contact links work.
  • Check spelling, service boundaries, image permissions, and business claims.
  • Make one edit in GitHub and verify that the public site updates.
  • Record domain renewals, owner login/recovery, and keep backups of both files.
  • Do not collect customer data through an unsecured frontend-only form.
